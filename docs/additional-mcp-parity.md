## User discovery implementation

[Eleven caller-bound tools](user-discovery.md) now implement user listing, ID/email
lookup, own profile, named profile fields, and substring/fuzzy candidates with
explicit ambiguity, presence/status, group membership and caller-specific mute
preferences. This overlaps `get_users`, `get_user`, `get_user_by_id`,
`get_user_by_email`, `get_own_user`, `resolve_user`, presence/status/group reads,
`update_status`, and mute/unmute operations; it does not claim full
reference cache/config or all user-management parity. Unit, wire, stdio and
authenticated HTTP isolation/revocation tests cover the implemented behavior.

## Integration rules and acceptance

- Preserve the existing user instruction against a custom frontend: implement enrollment/provisioning capability through authenticated API/CLI. Do not silently drop enrollment itself because the reference has a browser page.
- Identity switching selects only pre-authorized identities linked to the authenticated actor. It must not weaken the fixed-origin rule or let model arguments supply credentials or impersonate another user.
- Existing HTTP authentication remains required; local development conveniences in a reference are not permission to expose an unauthenticated production endpoint.
- Optional external providers remain opt-in and configurable. Tests must distinguish real provider execution from fixtures and data-only fallback; do not copy model defaults as permanently current facts.
- Inspect function behavior and runtime registration paths, not only the name inventory, before marking a row complete. Include regression, identity-isolation, policy-bypass, persistence/restart and protocol tests.
- Recheck all three upstream default branches before release and review changes since these pins. A green REST catalog gate does not imply reference parity.
- All rows stay required until completed with evidence or the user explicitly changes scope. Hermes remains excluded. No reference source code has been copied into the package by this inventory.
